How to read this, and what it cannot tell you

Scope defaults to build-type agents (build, Sisyphus, BuildAgent, beads-task-agent, general) because explore, plan and librarian sessions read by design and would make any model used for exploring look unproductive. Sessions are attributed to the model that produced most of their replies; 96% have one model at 80% or more.

Selection bias is real and not removable: heavy models get hard tasks, cheap models get lookups. Models were also used in different eras with different tooling. Read this as how each model performed in the work you actually gave it, not as a benchmark. Zero-cost entries were served on plans that record no per-token cost; they sit in the left band and are excluded from the per-dollar view.

Definitions and limits

Verified counts a session once if any shell command matched a build, test, type-check or lint tool (pnpm build, tsc, vitest, jest, pytest, go test, eslint, biome, ruff and similar). Committed matches git commit. Edit failures are edit or write tool calls that returned an error. Edits per file is edits divided by distinct files touched; it is blank where the provider did not record file paths. Bars in the table are scaled to the column maximum among the rows shown.

Same caveats as the productivity map: build-type agents only by default, sessions attributed to their dominant model, and the model you chose for a task depended on the task.

Shipping in commits

The unit here is a git commit, one per feature, read straight from the 21 repositories: your own commits on every branch, merges and bots excluded. The role option separates a model's planning work from its building work, or pairs the dominant planner with the dominant builder in each commit window. Each commit is shared out across the sessions that were active in that repository since the previous commit, weighted by active time, and each session's share goes to its dominant model. Commits with no agent activity in their window are the manual bucket. Lines come from git, so they cover every era.

How attribution works, and where it is soft

A commit's window runs from the previous commit in the same repository to the commit itself, capped at 72 hours, with 5 minutes of grace after. Sessions with messages inside the window split the commit in proportion to their active minutes. Prompts per commit credits each session's prompts to the window in the same proportion. Median lines are weighted by attribution share.

This is inference: a commit can include manual edits made alongside the agent, and a window can contain work for more than one feature. Commit size also varies by repository, which is why lines per commit sits on the map rather than being ignored. Scope defaults to all session types because exploring and planning are part of shipping; the commit is what closes the loop.

Method and caveats

Estimate, not wall clock. Active adds min(delta, 10 min) per message plus 60 s seed. Excludes system, synthetic and compaction messages.

Cost and token sums come straight from session records, split across message days by active time. Fresh tokens equal input plus output plus reasoning; cache reads (13.6B) are reported separately.

Models over time counts assistant messages by the model field on each message; session records only keep the last model used. All dates and hours are UTC.
