# AGENTS.md - Coding Agent Guidelines for ocInsights

## Project Overview

Analytics deck over the opencode session database (`~/.local/share/opencode/opencode.db`, SQLite) and the git history of the projects under `~/dev`. Live path: an OpenCode plugin (`oc.insights`) that exposes the data on `http://127.0.0.1:4173/` by running `plugin/metrics` in a Bun Worker on request. Snapshot path: one self-contained HTML file built locally (`make`). Measurement is TypeScript (`bun:sqlite` + `git log`); the deck itself is vanilla HTML + JS with no framework and no runtime dependencies.

Read `README.md` first — it holds the metric definitions. This file is about working on the code.

## Build / Run / Verify Commands

```bash
make                 # extract + build + verify (~20 s)
make extract         # bun plugin/cli.ts extract --out data.json   (read-only DB pass + git log)
make build           # bun plugin/cli.ts build                     (data.json + template.html -> deck)
make verify          # node verify.mjs opencode_time_full.html (headless Chromium, 124 checks)
make contribute      # send changed rows now (auto-send runs on its own; on|off|status manage it)
make contribute-preview  # dry-run the payload + privacy grep (no network)
make template        # bun plugin/cli.ts template — only after hand-editing a built deck
make install-plugin  # bun install + add this repo to global plugins; removes old editLedger.ts symlink
make serve           # bun plugin/serve.ts — HTTP without OpenCode (http://127.0.0.1:4173/)
make ledger          # what the edit ledger has collected, plus the last plugin load/fail line from opencode.log
make smoke           # one write through a fresh `opencode2 run` in /tmp; proves the ledger hook records
make smoke-http      # bun plugin/smoke.ts — HTTP /health only, no extract
make typecheck       # bunx tsc --noEmit
make publish-npm     # typecheck + npm pack --dry-run + npm publish --access public
```

No test framework beyond `verify.mjs`. No linter configured. A quick JS syntax gate you can run after editing the template:
`node -e "const h=require('fs').readFileSync('opencode_time_full.html','utf8');new (require('vm').Script)(h.match(/<script>([\s\S]*)<\/script>/)[1])"`.

## Language Choice

TypeScript throughout: `plugin/metrics/` (measurement, `bun:sqlite` + `git log`), `plugin/build.ts` (string replace), `plugin/cli.ts` (snapshot commands), the OpenCode plugin. The deck's JS is plain ES2020 in `template.html`; keep it dependency-free so the snapshot opens anywhere with no build step. Plugin TypeScript is 2-space. Do not reintroduce Python.

## Code Style

- Config constants live at the top of `plugin/metrics/config.ts` with a comment each; do not scatter magic numbers. `plugin/ledger.ts` imports `EDIT_TOOLS` from there.
- Plugin TypeScript is 2-space, matching the OpenCode plugin examples. Keep `@opencode-ai/plugin` as a runtime dependency (RPC). The HTTP server is a process-wide singleton (`plugin/server.ts`); do not listen in every location's `setup`.
- Template JS is dense by design (one file, no build step). Each chart is an IIFE or a factory (`stacked()`, `commitsCard()`, `profileCard()` for the turns and overall cards, configured by a `*_CFG` object); shared helpers are `bindTip`, `row`, `makeSortable`, `setHot`, `fmtT`. Reuse them. Selection state in `profileCard` is `hot` (hover), `iso` (legend isolate) and `cmp` (overall-only two-pin compare, `P.compare`, delta panel in `#ocomp`); all visibility flows through `paintSel()`, which `spot()` calls on every hover change.
- Placeholders in `template.html` are `@@NAME@@`. Data constants are `const NAME=@@NAME@@;`. `renderDeck` asserts none are left unfilled.
- Design language is the PF Console one (`~/dev/datastudio/.design-sync/conventions.md`): everything square (`border-radius:0` is enforced globally), burnt-amber primary, semantic tokens, IBM Plex Sans for copy and Inconsolata for every machine value, sentence case, no emoji. Charts use `--chart-1..5` and family hues; nothing neon. Radar axis labels, spokes and background wedges are keyed on `ax.hi`: `--chart-2` (green) when higher is better, `--chart-5` (red) when lower is better, matching pragma's strip bands. Radar display order groups the green axes at the top (`P.radarGroup` partitions hi-first on overall, `P.radarRot` rotates them up on turns) then swaps `lat`↔`ttss` so Time/step sits where Turns/ship was; strips and tables keep tier order. No sector fill; primary axes read off bold labels. Profile cards default to raw orientation (`torient='raw'`): outward/right is more, direction reads off the green/red radar encoding and the strips arrows.

## Architecture

Live: OpenCode loads `plugin/index.ts` (`oc.insights`). `setup` registers the edit-ledger hook and a process-wide HTTP server on `127.0.0.1:4173` (`OC_INSIGHTS_HOST=0.0.0.0` or plugin option `host` to listen on all interfaces). A request that misses the 5-minute cache runs `plugin/metrics` in a Bun Worker (`plugin/metrics/worker.ts`) writing `~/.local/share/ocInsights/data.json`, then serves that JSON or injects it into `template.html`. If the Worker fails to load, extract falls back to `bun plugin/cli.ts extract`. RPC `ocInsights` `{status, refresh, get}` is a thin pointer at the same server. Do not extract in `setup`. Open the SQLite connection inside the worker (connections are per-VM); never share a `bun:sqlite` Database across threads. On first load, `plugin/config.ts` renames `~/.local/share/ocProductivity` to `ocInsights` if the new path is absent.

Snapshot: `bun plugin/cli.ts extract` → `data.json` → `bun plugin/cli.ts build` → `opencode_time_full.html`.

`plugin/metrics` does one ordered pass over `session_message` (`ORDER BY session_id, time_created, id`) and computes everything per session in a single map: heartbeat credit, dominant model/provider, prompt and reply counts, tool calls (errors split into model errors vs human aborts via `ABORT_RE` on `state.error.message`, with the `before .*migration` backfill artefact excluded from both), verify and commit commands, per-session and per-cycle last-edit/last-verify timestamps for the tree verified flag, plus the plan→build cycle split (a new cycle starts when a plan assistant message arrives in a cycle that already did build work; the user turn that prompted it moves to the new cycle). All datasets are rolled up from that pass, then `attributeCommits()` joins git commits to cycles by time window. Adding a metric means adding a field in `scanMessages()` (session, phase and cycle level together) and rolling it up in `plugin/metrics/index.ts` — and asking whether `../pragma` should follow (see Downstream). Stream `session_message` with `stmt.iterate()` — never `.all()`.

`plugin/build.ts` formats `meta` into KPI strings and injects each dataset as JSON. `RANGE` (start, end, window start, calendar weeks, session count) is injected too so the JS has no hard-coded dates.

Raw records injected into the deck: `SESS` (one row per session; columns in `SESS_COLS`, names resolved through `IDX`; `pm/pp/bm/bp` are the plan-phase and build-phase dominant model/provider, `pv/bv` their dominant effort variant, `variant` the session's own, `ocv` the session's harness version), `PH` (one row per session phase, columns in `PH_COLS`; a phase is the part of a session run under one agent role; carries its own `variant`), `CYC` (one row per plan→build cycle, columns in `CYC_COLS`; `sess` links the parent `SESS` row, `pm/pp/bm/bp` are the cycle's own pair, `pv/bv` its phase variants, `pu/pa/pedits/bu/ba/bedits` the plan/build side breakdown, tree fields folded per cycle), `DAYW` (day → worktree → hours by role code `[all, plan, build]`), `DAYM` (day → `model|provider` → messages by role code), `DAYU` (day → your prompts / subagent prompts / replies), `RHYD` (day → 24 hourly counts), `DTOK` (day → tokens, cost, sessions), `CM` (commits with attribution; entries carry an 8th element, the variant index into `CM.variants`), `PSRC` (month → `[edit calls, with path in message JSON, part-table records, ledger records]`; sources overlap, never stack them), `LEDGER` (`{lines, sessions, first, last, last_edit}`), `RANGE`.

Render-time derivation (`derive()` in the template) turns those into the per-card datasets under `FILTER = {win, role, small}`: `HM`/`HMR`/`PORDER` monthly hours (by project / by role) · `HD` daily hours · `DMODELS` models per day · `PROD` = `SHIP` per-model records for productivity, shipping, the funnel and the turns card · `UA`/`UAM` who is talking · `DHRS` for the tokens grid · `LB`/`COST`/`DEPTH` the projects table · `AGENTS`/`MODELS`/`RHY` sidebar cards · `KPI` for the header (hours, turns to ship, edits, commits, cost, tokens). `aggBy(rows, hrows)` sums legacy fields from `rows` and the human-turn (`h*`) family from `hrows`: off/split keep session/phase rows for legacy and take `h*` from cycles (`cycHRow` keeps parent keys, `cycSideRow` keeps parent-phase keys with build > plan > other ownership); combo uses full cycle rows (`cycComboRow`) for both, so each cycle lands on its own pair. All three level-1 keys carry the dominant variant (`M|P|V|b`, `M|P|V|role`, `pm|pp|pv|bm|bp|bv`); the model/family/provider views collapse it in `keyOfMP`, the `effort` grouping (`m:v`, family colours) keeps it. `HVER` (month → version bucket → sessions + raw versions) feeds the harness strip and the `k_ocv` header chip. The `h*` family is `hu/ha/hjudged/hshipped/hshipped_costed/hu_ship/hedits/hedits_ship/hteerr/hcost/hcost_ship/hhrs/hhrs_ship/hver/habort/hshipj/hshipu/hshipcost/hpend/himposs/hone` — shipped-conditional sums (`hu_ship`, `hedits_ship`, `hhrs_ship`, `hcost_ship`) over shipped cycles only, ship-judged sums (`hshipj` count, `hshipu` turns, `hshipcost` cost) over cycles whose ship outcome is knowable, dollars over `hshipped_costed` (shipped cycles with `tcost>0`) only, the rest over judged cycles, plus `latBag` (`[cycle-median seconds, steps]` pairs for the latency axis, judged cycles with valid steps only). The overall card reads only the `h*` family (no legacy fields); its ten axes group into six tiers (`OVERALL_CFG.tiers`, weights 30/20/15/15/10/10) scored as the weighted mean of tier means on a fixed ±2 log span, with per-axis kinds (`ratio`/`odds`/`err`) in `relOf`, within-tier redistribution for missing axes and pool imputation (`50*`) for a wholly missing tier. `renderAll()` clears every container (`resetDom`) and re-runs the card code; local card state survives in `UI`. Extract still emits the legacy pre-aggregated datasets in `data.json`, but `build.ts` only injects the raw ones. The deck is ordered Time → Inputs → Output → Outcome → Projects → Method; the two commit views are one card with a y-axis toggle.

## Data Facts and Gotchas (each of these cost real time)

- **Line counts end on 2026-06-05.** `session_v2.summary_additions/deletions` are populated through opencode 1.15.13 and never after 1.16.2. Any per-model chart on lines silently shows recent models as producing nothing. Use edits (tool calls) as output; lines are a legacy column only.
- **Line counts on child sessions are wrong anyway.** 153 subagent sessions show lines they never edited — the summary reflects the shared worktree, not the session's own work. Another reason edits are the output metric.
- **Per-message tokens exist on ~10% of messages** (recent versions only). Day-level tokens come from splitting `session_v2` totals across message days by active time.
- **`session_v2.model` is last-used only.** Per-message `model` fields are the truth (125 mid-session model switches). Always parse the message JSON.
- **Tool parts are `{"type":"tool","id":...,"name":...}`** — the key is `name`, not `tool`, and `providerState` nests braces, so regex on message JSON undercounts by ~70%. Parse with `JSON.parse`; the full pass is ~7 s.
- **Model ids come in four spellings** across providers (`claude-opus-4-6`, `claude-opus-4.6`, `anthropic/claude-opus-4.6`, `claude-opus-46`). `canon()` is the single normaliser; use it everywhere a model id is read.
- **Effort variant is a per-message field, 100% populated since Jan 2026** (`data.model.variant`: `default`/`high`/`max`/`xhigh`/`medium`/`thinking`; 297 sessions switch mid-way, so it is counted per message, never taken from `session_v2.model`). The `mp` counter key is the `model\x1fprov\x1fvariant` triple; `topPair()` sums over variants first, so dominant pairs are byte-identical to the pre-variant count, and `topVariant()` picks the dominant variant within the pair (first-seen wins ties in both). Surfaces as SESS `variant`/`pv`/`bv`, PH `variant`, CYC `pv`/`bv`, the 8th commit-entry element, and the deck's `effort` grouping (`m:v`); `DAYM` stays `model|prov` (the models-per-day card has no effort toggle).
- **Harness version is per session** (`session_v2.version`, zero nulls: `1.x.y` releases and `0.0.0-beta-N` builds). SESS carries the raw string as `ocv`; PH/CYC inherit through `sess`. `versionBucket()` (TS) and its `ocvBucket` mirror in the template bucket to minor (`1.18`) or `beta` for charts; the harness name is the `HARNESS = "opencode"` constant, per-row in the contribution so a second harness can join later.
- **GPT/OpenAI providers do not record edited file paths**, so edits-per-file is blanked for them (`files < edits/20` rule), their shipped column is blank, and their commit credit comes only through the time fallback (the tooltip says so).
- **Edit paths: three sources, the message JSON is still primary.** `state.input.path` (not `filePath`) carries the path on every edit/write part through September 2026 (2,461 of 2,461 September parts). An earlier note here claimed September had none — that was a mis-measurement (`"filePath"` LIKE filter), not a schema change. Feb–Aug paths are also in the legacy `part` table (`partEdits()`, over-counts by up to 2x in Feb), and from September our own ledger records them too (`plugin/ledger.ts` → `~/.local/share/ocInsights/edits.jsonl`, `ledgerEdits()`). All three are unioned per session before `attributeCommits`; `PSRC` (month → `[edits, msg, part, ledger]`) and the deck's *edit-path coverage* strip show each source's share so the day the message JSON stops carrying paths is visible, not silent.
- **Auto-contribute scheduler (`plugin/scheduler.ts`).** On by default; effective switch is env `OC_INSIGHTS_CONTRIBUTE` → option `contribute` → `contributor.json` → on. First send ~15 min after load (first-install grace so the user can opt out), then every 6 h, each gated on 10 min without session events (`session.*` execution/tool/step/text prefixes). Sends are diff-based against `contributed.json` (per-row sha256; a schema/extractor/url mismatch resends everything); every successful send records all current hashes. Network failure → `lastFail`, 1 h backoff; HTTP 400 → parked until restart (manual sends unaffected). Coordination across processes is the on-disk `lastSent`; the in-tick `sending` flag plus the `runContribute` lock serialise within a process. Hot-reload generations share `{start, lastActive, parked}` through a `globalThis` symbol but own their timer (old cleanup stops the old loop). The interval is `unref`'d so short-lived `opencode run` processes exit on time. `getStatus()` (files + scheduler state, never extracts) feeds `/health`, RPC `contributeStatus`, the deck chip/panel and the TUI dialog — never put the install id in it.
- **TUI plugin (`tui.ts` → `plugin/tui.tsx`, id `oc.insights.tui`).** Loaded like the server side from a root entry (`"./tui"` export is belt and braces — the loader resolves `<dir>/tui.ts`). Server↔TUI talk only through RPC methods (`contributeStatus`, `setContribute`, `status`, `contribute`) and the `contributed` event; RPC results arrive `unknown`, so `tui.tsx` adapts them (`asShare`/`asUrl`/`asContrib`). There is no open-URL helper: `/insights` spawns the platform opener and always toasts the URL as fallback. One keymap layer per command so a rejected bind can't take down the other; command ids are `oc.insights.deck` (`ctrl+alt+i`) and `oc.insights.contribute`; `ctrl+alt+i` is overridable via `cli.json` keybinds by command id. No footer chip: status lives in the deck header chip (hidden by default, `pt-share-chip` localStorage flag, toggled from its Contribute panel) and the `/contribute` dialog refreshes on open. Mirror oc2Usage (`../oc2Usage/src/tui.tsx`) for Solid idioms (slot/keymap disposal).
- **Directory plugins resolve to `<dir>/index.ts`.** opencode ignores `package.json` exports when loading a plugin directory — the entrypoint is literally `<dir>/index.ts`, and a directory without one is skipped with no log line at all. This repo's real plugin is `plugin/index.ts`; the root `index.ts` is a one-line re-export that must stay. (Lost a day: zero load attempts in three months of logs.) npm-form installs (`"plugin": ["@pfoundation/ocinsights"]`) resolve through `package.json` `exports` (`"."` → `plugin/index.ts`, `"./tui"` → `plugin/tui.tsx`).
- **The plugin serves both plugin APIs from one entrypoint.** `plugin/index.ts` default-exports a plain `{ id, setup, server }` object (`Plugin.define` is the identity function, so no wrapper is needed): v2 hosts call `setup(ctx)` and ignore `server()`, while v1 hosts (verified on opencode 1.18.21, which loads the function form and `{id, server}` but refuses `{id, setup}`) call `server(input, options)` and ignore `setup()`. V2 hooks through `ctx.tool.hook("execute.after", ev)` (`ev = {tool, sessionID, agent, messageID, id, input, status, result|error}`); the v1 shape (`export const X: Plugin = async ({directory}) => ({"tool.execute.after": …})`) is refused by v2 hosts with "Plugin must export a default definition with an id and an effect or setup function" (seen live for subtask2/dcp/handoff); load failures are only visible in `~/.local/share/opencode/log/opencode.log` (or `--print-logs`). V1 details: the after-hook input is `{tool, sessionID, callID, args}` with no agent (ledger writes `""`, which extract never reads) and no status (every call is recorded; a failed edit's phantom path is harmless); the `event` hook feeds `noteActivity()` for scheduler quiet-gating; options arrive only via a `[package, options]` tuple, otherwise env/`http.json` apply; `package.json` needs `"main"` (same file as `exports["."]`) for the v1 npm convention. The v1 path must keep zero runtime `@opencode-ai/*` imports (`Plugin` is type-only, `rpc.ts` loads lazily inside `setup()`), because a v1 host resolves that package to the v1-stable line which has neither `define` nor `/rpc`. V1 loads location plugins lazily (nothing runs until a session boots the location) and installs npm entries asynchronously at startup into `~/.cache/opencode/packages` (a fresh install is absent on first boot). V1 skips RPC, TUI and the agent tool. The running server hot-reloads a plugin file on mtime change, so an edit takes effect without a restart — except imported modules: an edit to `plugin/build.ts` (or any file imported by the entry) is not picked up until opencode restarts, and the page fails with `unfilled placeholders` in the meantime. Plugins are instantiated once per location (project directory); the HTTP server is a module-level singleton so only the first location binds the port (`127.0.0.1` by default, or `0.0.0.0` via `OC_INSIGHTS_HOST` / option `host`). `ledgerEdits()` dedupes on the tool call id (`call`) in case a hook fires more than once. `make smoke` proves the v2 ledger path and `make smoke-v1` the v1 one (isolated `XDG_CONFIG_HOME`, file adapter with no `node_modules` so it also guards the zero-runtime-import rule, pins `opencode/gemini-3.5-flash-lite` since xai OAuth is expired for v1); `make smoke-http` proves `/health`. `LEDGER` in `data.json` carries lines/first/last plus `last_edit` (newest edit in the DB); the deck shows a header chip when the ledger is inactive or more than a day behind the DB.
- **Paths must be made relative to `session_v2.directory`, not the project worktree.** 473 datastudio sessions ran in `/home/ubuntu/dev/v0-dashboard` before the rename, and some ran in opencode's temporary worktrees under `~/.local/share/opencode/worktree/`. `relFile()` is the single place this is done; using `project.worktree` as the base zeroed file-overlap for all of them.
- **Commit attribution is by file overlap** (`attributeCommits`): a cycle gets credit only if its recorded edits touched files in the commit. Active-but-untouching cycles are *advised only* and get nothing — a deliberate decision, not a gap. `recs[i][4]` is the basis (`files`/`window`); `manual[i][2]` is 1 for advised-only. The funnel's `s_commit` field now means *shipped* (edits landed in a commit within `SHIP_DAYS`), and `s_paths` is its denominator. Session shipped is the union over its cycles measured from the session start, so the session funnel is unchanged.
- **Ship-judged denominators.** The turns/overall ship rate divides by ship-judged cycles, not judged cycles. `tshipe` on `CYC`/`SESS` is 0 ship-judged, 1 pending (unshipped, `first + SHIP_DAYS` past the latest scanned commit), 2 unshippable (unshipped, window closed on a worktree outside the scanned repos or with no attributable commit in it); shipped trees are always 0. The deck sums `hshipj/hshipu/hshipcost` (count/turns/cost over code-0 cycles) plus disclosure counts `hpend/himposs`; only `shipr` and the per-ship turns/cost numerators (`tts`, turns `dps`, all-in `ttsAll`/`dpsAll`, header KPI) use them — process axes stay on judged. A group with zero ship-judged cycles gets `shipr: null`, which the existing null paths render as `—` with `50*` tier imputation. `attributeCommits` also returns per-repo commit timestamps for the gate; `CM.latest` is the censor line.
- **Session trees: human turns live on the parent.** Child (subagent) sessions carry exactly one `user` message — the delegation prompt — so human engagement is `u` on `child=0` rows. Extract folds each subtree into its top-level parent per cycle (`kids, tedits, teerr, tcost, tship, tpaths, thrs, tver, tabort, tshipe` on `CYC`, same ten on `SESS` at session level; each descendant lands in the cycle spanning its first message); a cycle tree ships if any session in it shipped, is verified (`tver`) if its latest verify ran after its latest edit, and carries tree active hours (`thrs`) plus an abort flag (`tabort`). The turns card judges a cycle only when its tree edited and has paths, and `cycSideRow()` hands tree facts to the build side (`ownerT`: build > plan > other), so plan rows are mostly unjudged under a split. `SESS` keeps session-level tree sums for compatibility.
- **Aborts are not errors.** `state.error` is `{type, message}`; `ABORT_RE` matches the human-stopped strings (`Tool execution aborted/interrupted`, `Task cancelled`, `The user rejected/declined …`) and those parts bump `abort`, never `terr`/`eerr`. The `…interrupted before …migration` string is a backfill artefact and bumps neither. This shifts the productivity/shipping `efail`/`terrp` slightly downward — that is the correction, not a regression.
- **`VERIFY_RE` is a tool-name list, widened Sep 2026.** It now covers `make`/`gmake`, `(npm|pnpm|bun|yarn)( run)? (test|check|verify|lint|build|typecheck)`, `(bunx|npx) tsc`, `node verify`/`verify.mjs`, `playwright test`, `cargo check|clippy`, `go vet`, `mypy|pyright` plus the old runners. Bare `make` can false-positive on prose (`echo make sense`) — rare, accepted. Session `ver` counts rose ~2x on the rewrite; the shipping funnel's verified band moved with it.
- **Zero-cost cycles stay everywhere except dollars.** ~20% of judged cycles (mostly opus-4.6 on subscription plans) record `tcost=0`. Their turns, hours, edits and ships are valid evidence and stay in every axis; only `$`-per-ship divides by `hshipped_costed` instead of `hshipped`, so subscription ships neither dilute the rate nor count as evidence (`ev.dps` is the costed count, and the tooltip shows the costed share when partial). Same rule on the productivity card: `dph`/`epd` divide by costed hours/edits (`chrs`/`cedits` in `aggBy`), never by all hours/edits.
- **Ranking floor: 10 judged cycles.** `profileCard` ranks only groups with `hjudged ≥ 10`; smaller groups stay in the table dimmed (`tr[data-unr]`) and unranked, outside the pool, the min–max stats, and the radar. `sample.ts` applies the same floor (`MIN_JUDGED`), so the site only ever sees ranked groups.
- **One-shot allows the approval turn.** A plan→build cycle holds ≥ 2 human turns by construction (your request plus the "go build it" approval), so one-shot means `u ≤ 2` when the cycle has a plan phase (`pm ≥ 0`), `u ≤ 1` otherwise — counted in `aggBy` from the cycle's own `pm`, which `cycHRow`/`cycSideRow` must carry (the parent session's `pm` disagrees whenever plan activity sits in a later cycle).
- **`time.completed` is a migration backfill before March 2026** (Jan opus steps read 100% ≥ 10 min, some 27 days) and anything over the 10-minute cap after that sat open on a human (permission/question wait). Latency keeps only `0 < completed − created ≤ HEARTBEAT_CAP_MS` and aggregates by median — never average step time.
- **Sum loops must seed.** `g[f]+=r[f]||0` yields NaN for any field missing from the group literal — `hu_all` NaN'd the productivity Edits/turn and Replies/turn columns until Sep 2026. Always use `g[f]=(g[f]||0)+(r[f]||0)` (shipping and profileCard already do).
- **Numeric fidelity.** `pyRound` is CPython 3 half-to-even on the exact IEEE value (not `Math.round` / `x * 10**n`). Role-keyed maps (`ph`) must be `Map`, not objects — integer-like keys would reorder. `mostCommon` / `firstMaxKey` keep first-seen on ties. Compaction rows still create a session entry. `session_v2 JOIN project` is `ORDER BY s.time_created, s.id` so SESS row order is stable across SQLite builds.
- **`git log --numstat` rename syntax**: `dir/{old => new}.ts` and bare `old => new`; `gitCommits()` resolves to the new path.
- **`idle_outcome` and `revert` are too sparse to use** (172 and 2 sessions).
- **The database is live.** Sessions in progress (including the one editing this repo) change totals between runs. Diffs against a published deck will drift by a few hours; commit attribution should match exactly for the same git state.
- **Commit dates:** author date is used; only 1 of 753 commits in the two big repos was rebased by more than an hour. "Now" for the window filters is the latest commit, not the wall clock, so the deck is stable.
- **CSS class collisions.** The sticky page header is `.bar`; the funnel bars had to become `.fbar`. Check `grep -c` before adding a class.
- **SVG in Playwright:** `<text>` needs `textContent`, not `innerText`; decorative rings carry `pointer-events="none"`, so target `circle[data-s]:not([pointer-events])` when hovering.
- **Re-render discipline.** Every card runs inside `renderAll()`. Anything that appends to the DOM must be cleared in `resetDom()`; anything that registers a listener on a persistent element must assign (`el.onclick=`) or guard (`th.dataset.tb`), never `addEventListener` unguarded, or listeners stack on each filter change. Cross-highlight extensions go in `hotHooks[name]=fn`, not by wrapping `setHot`.
- **Commit entries are per cycle phase, and advisors are flagged.** `CM.recs[i][2]` entries are `[model, provider, role, share, prompts, hours, advisor, variant]` (variant indexes `CM.variants`). A credited cycle splits into its plan and build phases (share by cycle-phase time); plan-only cycles active in the window get an `advisor=1` entry with share 0. The off and split views must skip advisors; only the combo view reads them. Dropping planners from windows (which file-overlap credit does by construction) silently emptied the commit combos once — `verify.mjs` now guards it.
- **`session_v2.agent` is the LAST agent.** 595 of the 601 plan→build sessions carry `build`. Take roles from each assistant message's `agent` field (`AGENT_RE`), never from the session column, or plan time collapses from 293 h to 107 h. User messages take the phase in progress.
- **Session day.** A session belongs to the day of its first message for windowing; hours are still credited to the exact message day (`DAYW`). The two agree to within rounding over any window longer than a day. Cycles inherit the parent session's day — a cycle is in the window iff its session is.
- **Template literals:** `prefix + cond ? a : b` parses as `(prefix + cond) ? a : b`. Parenthesise ternaries when concatenating (it broke a summary line once).
- **Loading overlay.** `#loading` is static markup (paints before any JS) and is removed by `boot()` after the first `renderAll()`. The boot is deferred with `requestAnimationFrame` + `setTimeout(0)` (300 ms fallback for hidden tabs) so the loader paints before the first synchronous render. It only covers parse + render (~0.1–0.5 s locally). `window.onerror` writes the message into `.lmsg` instead of leaving it spinning; `verify.mjs` waits for the element to detach.

## Publishing

The deck contains cost figures and project paths — think before pointing a snapshot at a different audience. The live plugin defaults to loopback for the same reason; `0.0.0.0` is opt-in and unauthenticated.

npm package `@pfoundation/ocinsights`. The GitHub Release tag is the source of truth for the version (also the contribution `extractor` field): a published release triggers `.github/workflows/publish.yml`, which strips the leading `v` and overwrites `package.json` `version` via `npm pkg set` after install and before pack/publish (`bun install`, set version from tag, typecheck, `npm pack --dry-run`, `npm publish --access public --tag …`). Auth is npm trusted publishing (OIDC): the workflow carries `id-token: write` and no token, matched on npmjs.com by org `pfoundation` / repo `ocInsights` / workflow `publish.yml` with the `npm publish` allowed action (this is what proves the Release). Pre-releases (the release's pre-release flag, or a `-suffix` version as fallback) publish under dist-tag `next` so `latest` keeps pointing at the last stable; stable releases publish `--tag latest` explicitly. Pushing a tag alone publishes nothing — cut a Release. Locally: `make publish-npm` publishes `package.json` verbatim. The repo is public and the package is public, so provenance is generated automatically — no `--provenance` flag; `repository.url` must keep matching `github.com/pfoundation/ocInsights`. Trusted-publisher configs are case-sensitive and immutable: renaming the workflow file breaks publishing until a new config is created and the old one deleted. `files` must keep `plugin/`, `index.ts`, `tui.ts` and `template.html` — the live server injects the template.
