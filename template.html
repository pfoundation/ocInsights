How to read this, and what it cannot tell you

Scope defaults to build-type agents (build, Sisyphus, BuildAgent, beads-task-agent, general) because explore, plan and librarian sessions read by design and would make any model used for exploring look unproductive. Sessions are attributed to the model that produced most of their replies; 96% have one model at 80% or more.

Selection bias is real and not removable: heavy models get hard tasks, cheap models get lookups. Models were also used in different eras with different tooling. Read this as how each model performed in the work you actually gave it, not as a benchmark. Zero-cost entries were served on plans that record no per-token cost; they sit in the left band and are excluded from the per-dollar view.

Definitions and limits

Verified counts a session once if any shell command matched a build, test, type-check or lint tool (pnpm build, tsc, vitest, jest, pytest, go test, eslint, biome, ruff and similar). Shipped means the session's edits landed in one of your commits within @@ship_days@@ days; it is judged only for sessions whose edit paths were recorded, so the column is blank for OpenAI providers, which never record them. Edit failures are edit or write tool calls that returned an error. Edits per file is edits divided by distinct files touched; it is blank where the provider did not record file paths. Bars in the table are scaled to the column maximum among the rows shown.

Same caveats as the productivity map: build-type agents only by default, sessions attributed to their dominant model, and the model you chose for a task depended on the task.

Shipping in commits

The unit here is a git commit, one per feature, read straight from the @@repos@@ repositories: your own commits on every branch, merges and bots excluded. The role option separates a model's planning work from its building work, or pairs the dominant planner with the dominant builder in each commit window. Each commit is credited to the sessions whose edits, since the previous commit in that repository, touched the files in it, weighted by files touched, and each session's share goes to its dominant model. Sessions that were active but touched none of the commit's files get no credit: they advised, they did not ship. Commits with no agent activity at all are the manual bucket. Lines come from git, so they cover every era.

How attribution works, and where it is soft

A commit's window runs from the previous commit in the same repository to the commit itself, capped at 72 hours, with 5 minutes of grace after. Sessions whose recorded edits inside the window touch files in the commit share it in proportion to how many of its files each touched. Sessions that edited in the window but never had a file path recorded (OpenAI providers, and the gap before the edit ledger) fall back to a split by active minutes; the summary line reports how many commits used each basis. Prompts per commit credits each session's prompts to the window in proportion to its active time there. Median lines are weighted by attribution share.

Edit paths come from three sources: the message record, the legacy part table for February to August, and an append-only ledger written by a small opencode plugin from September on, because opencode stopped recording paths itself. A commit can still include hand edits made alongside the agent, and a window can contain work for more than one feature. Commit size also varies by repository, which is why lines per commit sits on the map rather than being ignored. Scope defaults to all session types because exploring and planning are part of shipping; the commit is what closes the loop.

Method and caveats

Estimate, not wall clock. Active adds min(delta, 10 min) per message plus 60 s seed. Excludes system, synthetic and compaction messages.

Cost and token sums come straight from session records, split across message days by active time. Fresh tokens equal input plus output plus reasoning; cache reads (13.6B) are reported separately.

Models over time counts assistant messages by the model field on each message; session records only keep the last model used. All dates and hours are UTC.
